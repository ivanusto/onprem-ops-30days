# 可維運檢查清單

Day 1 問的是「跑得起來」與「可長期維運」差在哪裡。三十天之後，差別可以寫成一張清單。每一條是一個可以回答是或否的問題，右邊是這個場域用什麼回答它、來自哪一天。拿到任何一套地端環境，照這張表問一輪，答不出來的格子就是下一張變更單。

這張表只列這個系列做過的東西，沒有常駐、要人去跑的在格子裡註明。沒做的列在最後一段「這張表沒有的」。

## 服務沒有被封裝（packaging）

| 問題 | 這個場域的回答 | Day |
|---|---|---|
| 每一個服務能不能從零重裝，而且裝出來與現在跑的一樣 | QPKG 薄殼，image 以 digest 鎖定，`SHA256SUMS` 隨套件 | 2、3 |
| 版本從哪裡來，誰改的，什麼時候 | git tag 觸發 GitHub Actions 打包與 release，release 附校驗碼 | 4 |
| 升級失敗怎麼回到前一版 | 前一版的 QPKG 與 digest 都在 release 裡，重裝即回退 | 3、4 |
| 需要硬體的服務（GPU、轉碼）是不是也能這樣裝 | 裝置直通與主機網路寫在生命週期腳本裡，Jellyfin、Roon、ComfyUI 各一個案例 | 5、7 |
| 把一個手工專案收回通用骨架省了什麼 | Open WebUI 重構記，差異在 Day 8 | 8 |

## 節點沒有被守護（node-guard）

| 問題 | 這個場域的回答 | Day |
|---|---|---|
| 這台節點要放什麼模型、放得下嗎 | 模型與硬體搭配矩陣，記憶體、儲存、頻寬三個數字 | 9 |
| 上游一改版，配方壞了怎麼辦 | 補丁移植的完整變更紀錄，上游修了就歸檔 | 10 |
| 節點裝好之後長什麼樣，誰能登入 | spark-baseline，帳號、SSH、初始設定可重跑 | 11 |
| 熱與記憶體到邊界時誰出手 | gb10-ops 的取樣器與自動降載，長時間負載量過 | 12 |
| 數字進了哪裡，誰看 | Prometheus 收集端，textfile 把前十八天的取樣器接進來，單一面板，告警分層 | 19、20 |
| 取樣器死了會不會沒人知道 | 每個 textfile 帶 `*_last_run_timestamp`，靜默失效是 warning 並抑制下游 | 19、20 |

## 儲存與備份沒有被治理（storage-backup）

| 問題 | 這個場域的回答 | Day |
|---|---|---|
| 模型庫誰能寫，被改了看得出來嗎 | NFS 單寫多讀，寫入鎖與權限凍結，`verify` 比對 manifest 的雜湊（沒有排程，進新模型時跑） | 13 |
| 儲存路徑選對了嗎 | RAID 60 與 RAIDZ2 試算，SSD、NFS、iSCSI 載入時間量過一次 | 14 |
| 一台節點掛了服務還在嗎 | PVE 雙節點 HA 加 QDevice VM，四個故障演練有數字 | 15 |
| 備份還原過嗎，花多久 | PVE、NAS、雲端三種還原演練，`drills.jsonl` 進指標，30 天與 90 天沒演練就告警 | 16、17、18、20 |
| 3-2-1 的第三份在哪裡，多少錢 | 異地物件儲存，保留政策與 Object Lock，成本表（演練用的 bucket 已刪，下一次演練要重建，`CloudDrillStale` 90 天會提醒） | 18 |
| 備份目的地自己有沒有備份 | 副 NAS 的快照與 HBS 3，Day 17 從零建 | 17 |

## 變更沒有被記錄（change-mgmt）

| 問題 | 這個場域的回答 | Day |
|---|---|---|
| 日誌在哪裡，留多久，能不能證明沒被改 | 節點不裝新代理，journald 上傳與 syslog 進 VictoriaLogs，每天封存 JSONL 進 WORM，`MANIFEST.tsv` 與 sha256 對帳 | 21 |
| 防火牆擋掉的東西有人看嗎 | 被擋的封包進日誌，降噪與自動化告警 | 22 |
| 日誌看不出原因時拿什麼補 | 最小權限的封包擷取，批次進 WORM，有金絲雀檔 | 23 |
| 稽核問某台機器上個月連去哪，答得出來嗎 | FortiGate AUP 雙軌，線上 LogsQL 與離線匯出檔同一份報告 | 24 |
| 哪些東西要到期了 | `eol/assets.tsv`，到期日進指標，授權風險以單子接受 | 25 |
| 誰在什麼時候改了什麼 | Markdown 變更單在 git，`check.py` 驗格式，`change-mark.sh begin` 與 `end` 寫 journal、Grafana 註記、silence | 26 |
| 機器留下的紀錄對得上單子嗎 | `audit-report.py` 把七種管理動作對窗，沒有單子的動作是告警 | 27、29 |
| 回退段真的做過嗎 | `drill.sh` 量回退時間，每張 high 的單沒演練就告警，90 天過期 | 28 |
| 代理程式可以碰什麼 | 閘道，沒有單子就沒有工具，不可逆要人以 sudo 核准，決定進雜湊鏈與 WORM | 29 |

## 這張表沒有的

- 交換器與 FortiAP 沒有接進日誌與指標，兩台交換器連 Day 25 的資產清單都沒有列。
- 兩台 NAS 都沒有回報 UPS，`qnap_ups_load_percent` 一直是 -1（沒有 UPS，或有但沒接訊號線），停電時 NAS 收不到關機通知，Day 30 也因此沒辦法用 UPS 量功率。
- QDevice VM 與其他小 VM 的 journald 沒有上傳（Day 27、29）。
- 收集端自己是單點，它掛了，指標與日誌一起停，Day 19 的靜默失效規則只能說「它停了」。
- 第二個人。核准、review、演練，整個系列都是一個人在做，`approval_exception` 寫在每一張單裡。
- 人力時間沒有量。Day 30 的成本表只有電與硬體，而且除了兩台 GB10 之外的瓦數是規格值。
- 六個 QPKG 與模型庫的 `verify` 都不在場域上常駐，它們的「還能用」只有發版當時的 CI 建置證明過。
